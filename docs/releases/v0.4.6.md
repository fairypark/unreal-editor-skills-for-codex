# v0.4.6 — Approved-plan blockout execution and repository validation

승인된 평면도와 블록아웃 사이의 차이를 확인하고, 독립 검토를 통과한 대표 구간을
실제 제작물로 전환하는 절차를 보강했습니다. 기존 로컬 지침을 검토해 공개
패키지에 반영하며, 자동 테스트와 재현 가능한 공식 검증 절차를 추가했습니다.

## 변경 내용

- 평면도의 버전·좌표·feature ID·허용 오차를 배치와 연결하고 매 작업 묶음 후
  실제 상태를 재조회합니다. 계획과 다른 배치를 사후 수정한 계획으로 정당화하지 않습니다.
- 블록아웃의 독립 검토, 제한된 수정과 재검토, 수렴 실패 시 원인 분석 및
  설계 재검토 경로를 정의합니다. 독립 검수자가 없으면 승격은 대기합니다.
- 대표 구간 안의 큐브 교체·메싱을 허용한 뒤 해당 구간의 임시 형상 퇴역을
  검증합니다. 전체 레벨을 먼저 교체해야 대표 구간을 시작할 수 있는 순환 조건을
  제거하고, 범위 확장과 최종 전체 승인 때 각각 검증하도록 했습니다.
- Handbook 미설치 시 plan-feature trace와 선언된 runtime camera 계약을 사용합니다.
  concept art는 승인 계약이 요구할 때 필수이며, 누락된 필수 증거를 면제하지 않습니다.
- 새 빈 레벨의 관찰 조명은 설계 승인 후 구성합니다. 기존 World Partition 모드와
  의도적인 어두운 조명을 보존하며 진단 화면을 최종 시각 승인으로 사용하지 않습니다.
- Windows GitHub Actions가 PR과 `main` push에서 회귀 검사와 공식 Plugin·Skill
  검증을 실행합니다. 실행 action과 공식 검증기 리비전을 고정하고 PyYAML 의존성,
  실패 종료, 시간 제한을 문서화했습니다.
- 인계 문서의 오래된 버전·초기 Skill 목록을 정리하고 실제 매니페스트와 릴리스,
  설치본, 새 세션 로딩 상태를 각각 확인하도록 했습니다.

## 검증과 적용 범위

- 회귀 검사 67개 통과. 사용량 수집 개인정보·동의 회귀를 포함합니다.
- 공식 Plugin validator 및 6개 Skill validator 통과.
- 변경 문서의 로컬 링크·앵커 22개, staged diff check 및 구성된 staged 비밀정보 검사 통과.
- 독립 정적 검토에서 찾은 순환 gate, Handbook 없는 실행 경로, partition 강제,
  concept art 강제 문제를 수정했습니다.

검증기는 [공식 OpenAI 리비전 985cf47](https://github.com/openai/codex/tree/985cf47a4eb6084b2ff6b30ebdb1216acda85bb4/codex-rs/skills/src/assets/samples)을
사용합니다. 로컬 실행과 CI 범위는 [VALIDATION.md](../VALIDATION.md)에 설명했습니다.

이 변경은 사용자 승인에 따른 Codex 확장이며 새 Epic upstream 포팅이 아닙니다.
upstream 기준은 `a6aa73ada02a9fb1f5415bec491f9942c519b297`로 유지합니다.
MCP 연결과 Hook, 사용량 수집의 동의·수집 범위는 변경하지 않았습니다.

지침·패키지 정적 검증은 실제 Unreal 장면의 렌더링, PIE, cook, 성능, migration
또는 전체 제작 완료를 증명하지 않습니다. 이번 릴리스에서 Unreal Editor를
변경하거나 새 환경을 제작하는 라이브 시험은 수행하지 않았습니다.
