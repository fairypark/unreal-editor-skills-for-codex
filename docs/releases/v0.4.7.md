# v0.4.7 — 여러 Unreal Editor에서 올바른 프로젝트에 연결하기

여러 프로젝트를 동시에 열었을 때 Codex가 어느 Editor에 연결됐는지 확인하는 절차를 추가했습니다. 프로젝트별로 포트를 고정하고, 수정하기 전에 현재 Codex 세션에서 프로젝트 경로나 Editor 프로세스 ID를 대조합니다. [Epic upstream 변경](https://github.com/EpicGames/unreal-engine-skills-for-claude-code-plugin/commit/0e27bde2b55c5d3f6948532f4296aaa3654d8f4b)

## 기존 설치를 업데이트할 때

공개 `v0.4.6`의 연결 파일은 문서와 달리 `8008`을 사용했습니다.
이번 공개 패키지의 기본 주소는 Unreal 기본값인 `http://127.0.0.1:8000/mcp`입니다.
Editor가 `8008` 등 다른 포트를 사용하고 있다면 프로젝트의 `.codex/config.toml`에
그 주소를 지정하고, 번들 연결과 프로젝트 연결 중 하나만 활성화하세요.
새 Codex 세션에서 읽기 전용 요청으로 대상 프로젝트를 확인할 수 있습니다. [설정 예시](../../skills/unreal-mcp/references/setup.md)

## 사전 검사 개선

- 직접 HTTP 연결을 점검할 때 프로젝트 Codex 설정, 프로젝트 MCP JSON, 번들 기본 설정 순으로 Unreal 항목을 찾습니다. 다른 MCP 서버 주소는 검사 결과에 포함하지 않습니다.
- 활성 프록시나 비활성 직접 연결을 만나면 해당 상태를 알립니다. 프록시 설치 기록에 남은 URL을 직접 연결의 근거로 사용하던 문제를 수정했습니다.
- 시작 로그에 기록된 포트 인수를 인식하고, 실제 서버 시작 메시지와 리스너 포트 및 소유 프로세스를 대조합니다. 여러 프로세스가 같은 주소의 후보로 나오면 수정을 보류합니다.
- 실제 Editor 식별 절차와 구버전 Engine에서 사용할 확인 방법을 문서화했습니다. [연결 점검 및 Editor 식별](../../skills/unreal-mcp/references/operations.md#identify-the-editor)

## 검증 범위

Windows 회귀 검사에는 프로젝트별 포트, 프록시, 실행 인수, 리스너 충돌, 공개 기본값과 기존 사용량 수집 동의·개인정보 검사가 포함됩니다. 공식 검증기로 Plugin 1개와 Skill 6개를 검사했습니다. 여러 Unreal Editor를 동시에 실행하는 실환경 시험은 이번 릴리즈에서 수행하지 않았습니다.
