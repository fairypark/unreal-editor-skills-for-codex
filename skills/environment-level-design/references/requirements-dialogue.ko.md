# 환경 제작 요구사항 대화 실행 — 한국어 검토본

영문 원문: [requirements-dialogue.md](requirements-dialogue.md).

환경 실행 요청에서 중요한 의도나 방향을 구체화하도록 도울 때 사용한다. 핸드북이 있으면 Chapter 04의 Collaborative requirements dialogue와 Chapter 15의 Requirements elicitation and direction-setting을 따른다. 이 문서는 그 대화를 실행 계약으로 전달하는 절차이며 새 설계 게이트를 만들지 않는다. 핸드북이 없으면 상위 스킬의 최소 대체 계약에 적용한다.

## 다음 결정을 준비한다

1. 기존 요청, 승인된 브리프, 참고 자료, 현재 단계, 앞선 답변, 관련 증거를 읽는다. 확정된 결정과 기존 권한을 재사용한다. 명확한 국소 수정에서는 미정인 범위와 후조건만 확인하고 전체 콘셉트 설문을 시작하지 않는다.
2. 이번 단계의 결과나 비용에 가장 큰 영향을 주는 미정 사항을 찾는다. 사용자의 취향과 AI가 조회할 수 있는 사실을 구분한다. 도구 이름, 에셋 경로, 카메라 속성, 기존 설정처럼 확인 가능한 정보는 허용된 읽기 전용 조회로 해결한다. 실제 Editor 조회에는 `unreal-mcp`를 사용한다.
3. 이해한 내용과 남은 선택이 중요한 이유를 설명한다. 이미지가 도움이 되면 실제 참고 자료나 현재 진단 시점에서 보이는 차이를 짚는다. 접근하지 못한 미디어를 봤다고 주장하거나 진단 시점을 승인 증거로 사용하지 않는다.

## 이해할 수 있는 질문과 방향을 제시한다

- 사용 가능한 사용자 입력 기능 또는 일반 대화를 사용하고 사용자의 언어로 묻는다. 결정에 중요한 질문을 소수씩 묶으며 모든 항목을 설문으로 제시하지 않는다. 이미 답한 질문은 제외하고 자유로운 답변도 가능하게 한다.
- 방향이 열려 있으면 서로 비교할 수 있는 구체적인 대안을 소수 제시한다. 추천안을 먼저 놓고 화면이나 플레이 결과, 추천 이유, 주요 장단점, 불확실성을 설명한다. 확인하지 않은 에셋, 소유권, 기능 지원을 실행 가능한 해법으로 단정하지 않는다.
- 구현 수치보다 경험과 화면의 결정을 먼저 묻는다. 메시 크기보다 랜드마크의 중요도, scatter 밀도보다 길의 개방감, 텍스처 파라미터보다 표면의 성격, packing 또는 instancing 방법보다 직접 조정해 유지할 예외의 역할을 먼저 다룬다.
- 사용자가 고르기 어려우면 참고 자료와 제약에 맞는 기본안을 제안하고 이를 시험할 관찰을 설명한다. 일상적인 선택을 위임했다면 기존 권한 안에서 결정한다. 미리 선택된 옵션이나 무응답은 제출된 선택 또는 승인이 아니다.
- 반드시 답이 필요한 경우 그 답에 의존하는 작업을 대기시키고 독립적인 승인 작업을 계속한다. 선택적인 취향은 적절한 경우 되돌릴 수 있는 가정을 명시해 진행하되 적용되는 단계 게이트를 약화하지 않는다.

## 상황에 맞게 선택할 질문 예시

아래는 조정 가능한 예시이며 필수 순서나 이미 정한 결정을 다시 묻는 요구가 아니다.

| 현재 미정 사항 | 제시할 질문 또는 방향 |
| --- | --- |
| “멋진 숲을 만들어줘”, 정서는 미정 | “처음 들어왔을 때 차분하고 반기는 느낌, 감싸이면서 신비로운 느낌, 노출되어 긴장되는 느낌 중 어느 쪽인가요? 주 참고 자료와 가장 가까운 방향을 추천합니다. 선택에 따라 시야와 동선의 리듬이 달라집니다.” 실제 참고 근거를 밝히고 만들어내지 않는다. |
| 차분한 정서는 확정, 구도는 미정 | “열린 숲 사이로 랜드마크가 계속 보이게 할까요, 조밀한 전경 군집 사이로 점차 드러나게 할까요? 열린 구성은 방향을 바로 알려주고, 점진적인 공개는 더 강한 동선 안내가 필요합니다.” 승인된 의도와 조회한 맥락으로 추천한다. |
| “더 자연스럽게”, 결함은 미정 | “같은 간격, 따로 떨어진 식물, 급격한 길 가장자리, 바위 주변 접촉 중 무엇이 가장 어색한가요? 현재 화면에서 보이는 문제를 먼저 고치고 같은 카메라로 비교하는 것을 제안합니다.” 이미지가 뒷받침할 때만 결함을 특정한다. |
| 주인공 형태와 가용 에셋이 다름 | “이 실루엣을 정확히 유지해야 하나요, 가용 키트에 맞춰 설계를 조정해도 되나요? 직접 조립하면 실루엣을 유지할 수 있지만 제작·검증이 늘어나고, 설계 조정은 통합 작업을 줄일 수 있습니다.” 조회하지 않은 가용성과 비용은 추정으로 표시한다. |
| “완성해줘”, 산출물은 미정 | “이번 목표는 플레이 가능한 블록아웃, 대표 시각 구간, 넓은 프로덕션 배치 중 무엇인가요? 각 범위의 결과와 필요한 검증을 설명하겠습니다.” 범위가 이미 명시됐다면 재사용한다. |
| 기존 이름이 있는 Actor를 2m 이동 | 승인된 설계를 계승하고 transform, 보호 범위, 관련 검사를 정의한다. 방향, 소유권, 계획이 소유한 관계가 실질적으로 모호할 때만 질문한다. |

## 답변을 기록하고 실행으로 전달한다

기존 브리프나 반복 기록에 선택한 방향, 근거 참고 자료 또는 이전 결정, 대상 구역과 시점, 우선순위, 보존할 요구, 관찰 가능한 목표, 남은 가정, 필요한 증거를 반영한다. 확정 의도와 제안한 대안·가정을 구분한다. 답마다 파일을 만들거나 새 공통 스키마를 강제하지 않는다.

도구, 그래프 파라미터, transform, 재질, 조명 수치를 정하기 전에 대화의 의도를 현재 단계의 계획과 수용 기준으로 옮긴다. 예를 들어 읽기 쉬운 랜드마크는 해당 시점의 주인공 실루엣과 공개 조건으로, 자연스러운 지피 식생은 군집 생태층·접촉 전이·분명한 길의 빈 공간으로 구체화한다. 수치 범위는 조회한 크기와 대표 시험에서 도출하며 근거 없는 기본값으로 확정하지 않는다.

해당하는 기존 계획, 번역, 에셋 준비, 수정 계약에 결정을 전달한다. 전제가 바뀐 결정만 다시 연다. 방향 선택은 에셋 취득, 넓은 재구축, 독립 시각 승격을 승인하지 않는다. 승인된 시스템을 보존하고 합의한 카메라로 수리를 비교한다. 기존 증거 무결성과 독립 검토 규칙을 해당 게이트에서 적용한다.

사용자가 자신의 의도를 알아볼 수 있고, 다음의 제한된 작업과 그 권한이 명확하며, 빠진 증거가 계속 표시되어 있으면 전달 준비가 됐다. 질문을 상세히 했다는 사실만으로 레벨이나 작업 방식의 검증을 주장하지 않는다.
