이 문서는 한 레벨에서 성공한 제작법을 다른 레벨·프로젝트·사용자도 다시
활용할 수 있게 보존하는 방법을 설명합니다. 여기서 생산 자산은 특정 메시나
재질 하나가 아니라, 검증된 배치 논리·필수 입력·금지 패턴·품질 통과 조건을
함께 묶은 재사용 단위입니다.

## 먼저 알아둘 세 가지 자산 형태

1. **프로젝트 원본 라이브러리**
   현재 프로젝트에서 승인된 실제 UAsset을 보관합니다. 원본 에셋, 의존성,
   고정 카메라 캡처, 해시와 출처를 함께 기록합니다. 다른 사용자가 같은 Fab
   에셋을 보유한다는 보장이 없으므로 이 폴더 자체는 보통 공개하지 않습니다.
2. **이식 가능한 시스템 계약**
   특정 유료 에셋에 의존하지 않는 JSON 문서입니다. 어떤 입력이 필요하고,
   PCG가 무엇을 책임지며, 어떤 시각적 실패를 금지하는지 정의합니다. 공개
   플러그인을 통해 누구나 받을 수 있는 부분입니다.
3. **Unreal Content Plugin**
   실제 UAsset까지 배포하는 별도 패키지입니다. 포함된 모든 파일의 재배포
   권한과 의존성이 확인된 경우에만 만들 수 있습니다.

에이전트의 기억이나 프로젝트 안의 비공개 폴더만으로는 공유 자산이 되지
않습니다. 다른 사용자도 쓸 수 있으려면 버전이 있는 공개 플러그인이나 별도
패키지가 존재해야 합니다.

## 가장 쉬운 사용 방법

Codex에 다음처럼 요청합니다.

```text
환경 레벨용 생산 자산 템플릿을 이 프로젝트에 설치해줘.
```

Codex는 플러그인의 설치 도구를 사용해 프로젝트 아래에 다음 폴더를 만듭니다.

```text
Docs/VisualQuality/ProductionAssets/Templates/
```

설치되는 파일은 다음과 같습니다.

- `ProductionAssetCatalog.template.json`: 프로젝트가 보유한 생산 자산 목록과
  승인 범위를 기록하는 장부
- `terrain-projected-gravel-route.system.json`: 지형 높이에 맞는 하나의 연속된
  자갈길을 만드는 시스템 계약
- `clustered-water-vegetation.system.json`: 패턴이 드러나지 않는 군집형 수생
  식생을 만드는 시스템 계약

직접 실행하려면 `skills/environment-level-design/` 폴더를 기준으로 다음 명령을
사용합니다. `<PROJECT_ROOT>`에는 `.uproject`가 있는 프로젝트 폴더를 넣습니다.

```text
python scripts/install_production_asset_templates.py --project-root <PROJECT_ROOT>
```

기존 템플릿이 있으면 설치 도구는 덮어쓰지 않고 중단합니다. 내용을 확인한 뒤
정말 교체해야 할 때만 `--force`를 추가합니다.

## 프로젝트에 적용하는 순서

1. 설치된 시스템 계약에서 `required_inputs`, `responsibilities`,
   `required_parameters`, `hard_failures`를 읽습니다.
2. 프로젝트가 합법적으로 보유한 메시·재질·PCG 입력으로 각 슬롯을 채웁니다.
   공개 계약은 Fab 에셋 자체를 포함하지 않습니다.
3. 처음부터 전체 레벨에 뿌리지 말고 대표적인 10–30m 골든 슬라이스에만
   구현합니다.
4. Visual Recipe의 고정 Camera Actor에서 캡처하고 독립 비주얼 감독의 평가를
   받습니다. 적용되는 모든 항목이 4/5 이상이고 하드 실패가 없어야 합니다.
5. 통과한 시스템만 프로젝트 원본 라이브러리에 복제하여 보존하고 카탈로그에
   출처·의존성·승인 캡처·적용 범위를 기록합니다.
6. 다른 레벨에서 다시 사용할 때는 `REVALIDATION_REQUIRED` 상태로 시작합니다.
   이전 레벨의 승인은 새로운 지형·조명·카메라에 자동으로 이전되지 않습니다.

## 자갈길 계약의 핵심

- 하나의 스플라인 또는 닫힌 경로 경계가 길 전체를 책임지게 합니다.
- 자갈을 생성하기 전에 위치와 회전을 신뢰할 수 있는 지형에 투영합니다.
- 작은 둥근 자갈을 조밀하게 깔고 큰 돌은 낮은 빈도의 강조 요소로만 씁니다.
- 여러 생성기가 같은 구간을 따로 처리해 겹침 이음새가 생기지 않게 합니다.
- 장식용 자갈은 `NoCollision`, Overlap Event 비활성화, Navigation 비영향을
  기본으로 합니다.
- 중앙선 돌사슬, 시멘트 띠, 공중에 뜬 돌, 균일한 타일 경계가 보이면 실패입니다.

## 수생 식생 계약의 핵심

- 식물을 균일하게 흩뿌리지 않고 크기와 밀도가 다른 비대칭 군락으로 만듭니다.
- 잎 하부층은 조밀하게 겹치고 꽃과 미세 강조 요소는 별도 저빈도 분기로 둡니다.
- 물가 접촉 구간과 의도적인 열린 수면 통로를 동시에 보존합니다.
- 줄기와 반복되는 밑동은 수면 아래로 숨기되 잎의 실루엣은 유지합니다.
- 장식용 수생 식생 역시 기본 충돌과 Navigation 영향을 끕니다.
- 격자·동심원·균일한 꽃 간격·드러난 반복 밑동이 보이면 실패입니다.

## 실제 UAsset을 다른 사용자에게 배포하려면

Asset Registry 의존성 보고서를 만들고 모든 직접·간접 의존성을 프로젝트 소유,
엔진 제공, 재배포 가능, 사용자 제공 필요, 배포 금지로 분류해야 합니다. 배포
금지 의존성은 슬롯이나 사용자 제공 요구사항으로 바꾸고, 선언된 의존성만 있는
깨끗한 프로젝트에서 설치와 로드를 시험합니다.

이 검사를 통과하지 못했다면 UAsset을 공개하지 말고 시스템 계약과 템플릿만
공유합니다. 이 방식이면 제작 노하우는 여러 사용자에게 전달하면서도 Fab 또는
마켓플레이스 에셋의 라이선스를 침해하지 않을 수 있습니다.
